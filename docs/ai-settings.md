# Dataset explorer and AI accounts

Dataset Preview opens a full-screen, read-only workbook above Analysis. Back to Chat restores the same live chat DOM, results and pending proposal; streams continue while browsing. Overview contains all available governed tables, business metadata, a searchable dictionary and declared relationships. Each table loads on demand with at most 30 actual rows. Counts come from Parquet footers; dictionary values inspect at most 512 rows. IDs show at most three samples, other columns at most sixteen. Complete lists are labeled only when proven complete; numeric/date ranges explicitly identify sample versus table coverage. Blocked columns/tables are omitted and sensitive/authentication identifiers masked before serialization. Browsing requires sign-in and consumes no question or API allowance.

Snapshot identity includes the manifest and governed definitions. Refreshes must publish a new manifest. Metadata and samples are bounded in-process caches, not browser-persistent data. Cardinalities come from the existing matching published profile; missing measurements are labeled unverified. Join predicates and additional join conditions come from the semantic schema. Foreign-key labels are inferred only for declared joins to explicitly declared primary keys. The dictionary does not claim that all relationships are enforced database constraints.

## Settings and model selection

Profile & AI settings offers Pantree's shared OpenAI account or one personal connection to OpenAI, Gemini, Anthropic or Groq. Test Connection calls the provider's model-listing endpoint, without billable inference. Available models come from that credential's account and are filtered to supported text/tool families. This verifies access to model discovery, not sufficient billing balance or successful inference on every listed model. Provider responses must still pass the existing Pydantic analytical schemas and all PR #40 governance checks.

All users can select available compatible models without approval, from settings or the chat header. Selection affects subsequent requests. Runs persist the provider, model, credential version and billing mode before execution; those values survive paused PostgreSQL checkpoint recovery. Changing settings never changes a pending run. Replacing/removing a personal key revokes the old version immediately: a pending run using it fails explicitly on its next provider call. Changing the shared environment key similarly invalidates the old pin. Already-sent requests cannot be recalled. Switch back to Pantree default retains the stored personal connection for later reuse; Remove stored key clears its encrypted material.

Web adapters use OpenAI Responses forced strict tools, Anthropic forced tools, Gemini JSON-schema output, and Groq forced tools. There are no additional provider SDKs or orchestration frameworks. Existing LangGraph flow, confirmation, deterministic compilation, verification and grounding are unchanged. The selected main model handles every web call in that run, including lightweight tasks; the configured lightweight default is displayed for transparency and remains available to the existing CLI. CLI operations are operator tasks and retain their existing accounting path; account allowances apply to authenticated web runs.

## Protected configuration and migration

1. Back up the application PostgreSQL database and preserve its existing usage rows. Install the lockfile with `uv sync --locked`.
2. Set `CREDENTIAL_ENCRYPTION_KEY` to a Fernet key in the deployment's protected secret configuration. Generate it in a secure administration session with `uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Never commit its output or put it in client configuration. Use HTTPS and the existing production session settings. Without a valid encryption key personal credentials are unavailable; shared API and dataset browsing remain available.
3. Keep `OPENAI_API_KEY`, `MODEL_MAIN`, `MODEL_LIGHT`, and the existing `DAILY_BUDGET_USD`. Set `DAILY_USER_BUDGET_USD` (default $1) for ordinary users without an individual override. Both per-user and aggregate budgets apply. Administrators can update individual allowances in Profile settings; changes do not erase current expenditure.
4. Configure `PRICES` as a JSON object mapping model names to three nonnegative rates in USD per million **input, cached input, output** tokens. Prefer provider-qualified names such as `openai:<model-id>`. Unqualified existing OpenAI entries remain supported. Setting `PRICES` replaces the defaults, so include every shared model intended for inference and retain required existing entries. Maintain current provider/account pricing; model discovery does not return a reliable price catalog. Shared ordinary-user inference with missing pricing is blocked before billing and explains personal-key usage as an alternative. Selection itself remains unrestricted. Admin/personal calls with unknown pricing are allowed and explicitly counted as unknown cost, never displayed as free.
5. Application startup (`Store`, also reachable with `uv run python -c "from pantree_insights.store import get_store; get_store()"`) creates three additive tables: `ai_profiles`, `ai_credentials`, `api_calls`, with their owner/run/day indexes. Existing tables and conversations are retained. PostgreSQL startup also widens `usage.user_id` from VARCHAR(16) to VARCHAR(64), because the existing aggregate budget identifier exceeds 16 characters. The check is repeatable; widening preserves values. The migration role needs CREATE/ALTER privileges. For a restricted runtime role, execute the migration first with a maintenance role; existing databases may alternatively run `ALTER TABLE usage ALTER COLUMN user_id TYPE VARCHAR(64);` before startup. SQLite needs no column alteration.
6. Retain the encryption key across restarts and backups. Arbitrary key rotation makes old ciphertext unreadable; coordinate rotation by removing/reconnecting personal credentials, including pending runs. This release does not implement a multi-key rotation service. Old pre-PR41 paused runs have no trustworthy provider pin and are marked interrupted after restart; start a new analytical request. Existing completed histories remain readable.

Credentials are encrypted with authenticated Fernet encryption bound to owner, credential ID and provider. APIs expose only provider and last four characters. Keys never enter prompts, chat context, browser storage, API responses or normal logs. Fixed trusted endpoints, no redirects, isolated model-discovery caches and fixed sanitized provider errors prevent credential fallback or cross-account client reuse. The only added direct dependency, cryptography, was already present transitively through authentication.

## Usage accounting

Daily counters use UTC, displayed explicitly in the UI. Ordinary shared requests reserve both individual and aggregate dollars in one database transaction before each provider attempt. Reservations cover UTF-8 prompt/schema bytes, framing overhead, the output cap and the configured model rates. Actual input, cached-input and output usage reconciles the reservation once. Every interpreter, clarification/revision, contrast and analyst call goes through this boundary. New chats and model switches share the same daily counters. Existing question admission, output caps, timeouts, concurrency controls and SQL limits remain.

Confirmed rejections release their reservation. Timeouts, server errors, malformed usage, or a process dying after admission may have been billed; their conservative reservations remain held for that UTC day and are visible as unknown/pending cost. No automatic retry can double-spend a single reservation. Keep provider invoices as the billing source of truth: displayed costs are estimates using configured rates. Outstanding holds must be reconciled against provider evidence by an operator before any manual refund; this release intentionally has no automatic timeout refund. The next UTC day starts a new allowance without deleting the audit ledger.

Administrators are exempt from ordinary request/spending quotas. Personal-key inference is billed to the user's provider and exempt from shared spending allowances. Both remain subject to provider and application resource limits and appear separately in the daily usage ledger. The admin view shows users' request counts, allowances, shared spend/holds, and per-user/provider/model input, cached, output, call and estimated-cost totals. The existing shared aggregate protects ordinary users' use of Pantree credentials; admin shared-key usage is tracked separately as requested.

No production deployment is part of this change. Live inference compatibility/accuracy, invoice reconciliation, production-scale latency and all-provider account entitlements still require a separately authorized validation run.
